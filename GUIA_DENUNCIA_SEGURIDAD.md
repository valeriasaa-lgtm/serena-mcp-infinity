# Guía de denuncia y seguridad — Serena MCP

## 1. Evaluación general de las plantillas originales

### Fortalezas
- Estructura clara (hechos documentados + solicitud específica + plazo).
- Incluyen evidencia concreta (hash del archivo, fecha/hora, vocabulario único).
- Mencionan posibles escaladas (autoridades de protección de datos).
- Son formales en tono.

### Debilidades / Riesgos
- Algunas afirmaciones son muy categóricas sin adjuntar prueba irrefutable.
- Fechas en 2026 y referencias a “Codex” pueden necesitar precisión técnica.
- Falta de detalles sobre cómo exactamente se produjo la extracción.
- Los placeholders deben completarse correctamente.
- Enviar a múltiples direcciones a la vez puede diluir la respuesta.

## 3. Consideraciones importantes

- **Adjunta evidencia real:** capturas de pantalla con timestamps, export de logs, hashes verificables, timeline de eventos.
- **Derechos:** en Europa/Argentina tenés derechos fuertes de acceso, rectificación y supresión (RGPD / Ley 25.326).
- **Explicación técnica alternativa:** revisá si usaste Code Interpreter, Copilot Workspace, o extensiones VS Code que indexan el workspace.
- **No publiques públicamente todavía:** evitá que parezca una campaña de desprestigio antes de tener respuesta oficial.

## 4. Próximos pasos recomendados

1. Cambiar todas las contraseñas y activar 2FA fuerte.
2. Revisar permisos de aplicaciones en GitHub (Settings → Applications).
3. Documentar todo en un archivo local (fechas, IPs, etc.).
4. Si tenés base en Argentina/Europa, contactar AAIP o equivalente paralelamente.
5. Considerar consultar un abogado especializado en derecho digital y propiedad intelectual.
